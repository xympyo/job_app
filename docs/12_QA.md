Date: 2026-09-14. Workspace: D:\Moshe\JobApplications.

## Automated checks

- `npm run lint`: passes with no errors or warnings.
- `npm test`: 24 tests across domain/persistence, UI flows and mocked Supabase Auth.
- `npm run build`: production build succeeds; vendor chunks split. Current Zod package
  emits harmless Rollup annotation warnings. With no Supabase environment configured,
  the SDK is tree-shaken and its named chunk is empty; this is expected.
- `npm run test:db`: 10 PostgreSQL integration groups pass against the actual migration.
- `npm audit`: zero known vulnerabilities at verification time.
- `npm ci --dry-run`: lockfile install validation passes.

Business tests cover create/edit, reusable company and multiple sources, applications,
CV/vacancy snapshots, flexible stages and rejection stage, separate draft/final answers,
completion/character limits, due items, search/filtering, ready vacancies, unique companies,
freshness, malformed/oversized/unknown-key/null imports, unsafe URLs, fit explanations,
title/URL deduplication, preview/no mutation, merge/skip/keep and within-batch duplicates,
local persistence, stale saves, storage corruption/quota errors, cloud errors and CSV safety.

UI tests cover protected routes, explicit local entry, logout, job create/edit → prepare →
Applied → question persistence, recoverable database errors, preview/duplicate/confirm import,
and email/password rejection/success/session/logout with a mocked Supabase Auth service.

PostgreSQL tests create auth.users/auth.uid and anon/authenticated roles in PGlite, then
execute the actual SQL migration. They check owned CRUD, second-user isolation, denied
cross-owner insert/FKs, anonymous denial on every table/RPC, batch rollback, table whitelist,
spoofed ownership, committed RPC results, stale-write rejection, immutable snapshots,
history-preserving deletion restrictions, required answers/limits and rejection stage.
This is real SQL/RLS execution, not a text inspection of policy statements.

## Limits and release boundary

No production Supabase project or Vercel account was connected. Actual hosted Auth,
PostgREST/RPC behavior, account configuration, cross-device sync and deployment remain
to be smoke-tested using Moshe's project. Follow README connection steps, then exercise
sign-in → add job → apply → question → refresh → second device → sign-out. Disable public
signups and verify the deployed environment keys are public keys, not service-role keys.

Automated accessibility checks do not substitute for every screen-reader/browser/device
combination. No claim is made of exhaustive certification or real iOS/Android testing.
Full-backup restore UI and private PDF uploads are deferred; JSON export is available.
